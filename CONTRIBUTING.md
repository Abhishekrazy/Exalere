## 🤖 AI-Assisted Contribution Guidelines

We welcome contributors who use modern AI coding tools (such as Google Antigravity, Gemini Code Assist, GitHub Copilot, Claude Code, ChatGPT, Cursor, etc.). However, to maintain architectural integrity, code quality, and project stability, all AI-assisted contributions must strictly comply with the following standards:

### 1. Verification Responsibility
- **You are responsible for every line of code generated by AI**: Do not submit unreviewed or blind AI outputs.
- You must verify that generated code compiles, passes tests, and introduces no regressions.
- Always run static analysis before pushing:
  ```bash
  flutter analyze
  ```

### 2. Follow Repository Rules (`AGENTS.md` / `.agents/`)
- If using **Google Antigravity / Gemini Agentic IDE**, this repository includes preconfigured agent instructions in [`AGENTS.md`](AGENTS.md) and specialized workflow skills under [`.agents/skills/exalere-contributor/`](.agents/skills/exalere-contributor/).
- Ensure your AI agent complies with:
  - D-Pad navigation guidelines on Android TV.
  - Safe state management with `Provider`.
  - Non-blocking async operations and exception handling.

### 3. Disclosure & PR Summary
- Please mention in your Pull Request description if an AI assistant was utilized and briefly describe how the output was manually tested or validated.

## 🌿 Branching Strategy & Workflow

To maintain a clean and reliable release cycle, we follow this branching model:

| Branch | Purpose | Stability | PR Target |
| :--- | :--- | :--- | :--- |
| `main` | Production / Stable release builds | 🟢 Highest | Releases & Hotfixes |
| `staging` | Integration testing & pre-release testing | 🟡 Moderate | Completed features ready for release |
| `develop` | Active day-to-day development | 🟠 Active | Main development branch |
| `feature/*` | Individual new features / UI revamps | 🔵 In Progress | Target `develop` |
| `bugfix/*` | Fixes for issues found in develop/staging | 🔵 In Progress | Target `develop` or `staging` |

### Branch Flow
```
feature/my-feature ──► develop ──► staging ──► main (Release Tag)
```

## 🛠️ Development Setup

### 1. Prerequisites
- **Flutter SDK**: `^3.13.2` or later.
- **Android Studio / VS Code**: With Dart and Flutter plugins.
- **C++ Build Tools & CMake**: If compiling for Windows Desktop.
- **Android TV Emulator / Device**: Recommended for testing TV layout navigation.

### 2. Getting Started
```bash
# Clone the repository
git clone https://github.com/Abhishekrazy/Exalere.git
cd Exalere

# Install dependencies
flutter pub get
```

### 2. Configure Local API Secrets (TMDB)
Exalere keeps sensitive API tokens out of Git. Copy the template and fill in your keys:
```bash
cp secrets.example.json secrets.json
```
*(Note: `secrets.json` is already excluded in `.gitignore` and will never be tracked by Git).*

### 3. Run Locally
Pass `--dart-define-from-file=secrets.json` when running:
```bash
# Launch on Windows Desktop
flutter run -d windows --dart-define-from-file=secrets.json

# Launch on Android TV / Mobile Device
flutter run -d <device_id> --dart-define-from-file=secrets.json
```

### 4. Testing Android TV Navigation
Use the included PowerShell TV remote script to simulate D-Pad inputs from your PC keyboard:
```powershell
.\tv_remote.ps1
```

## 🧪 Pull Request Checklist

Before submitting your PR, ensure:
- [ ] Code passes `flutter analyze` with 0 warnings/errors.
- [ ] No hardcoded secrets, personal tokens, or API credentials.
- [ ] UI works cleanly across responsive window resizes and Android TV screens.
- [ ] If modifying navigation, all interactive elements remain accessible via TV D-Pad (`TvFocusable`).
- [ ] PR title follows conventional commits (e.g., `feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`).
